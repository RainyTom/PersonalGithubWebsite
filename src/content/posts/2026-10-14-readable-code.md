阅读一段陌生代码时，最先遇到的通常不是算法，而是名字。一个叫 `data` 的变量，可以装下任何东西，也因此几乎没有告诉读者任何信息。

## 让名字回答一个具体问题

看下面这个很小的例子：

```js
const publishedPosts = posts.filter(post => !post.draft);
const recentPosts = [...publishedPosts].sort((a, b) =>
  b.date.localeCompare(a.date)
);
```

`publishedPosts` 说明筛选后的集合代表什么，`recentPosts` 说明后续排列的用途。复制数组之后排序，还让调用方不必担心原始数组被修改。

这个例子假设日期都使用 `YYYY-MM-DD` 格式。如果数据来自多个接口，应先验证和统一日期格式，再采用字符串比较。

## 名字太难取，可能是职责太多

如果一个函数既获取文章、转换格式，又发送邮件，很难用一个简短的动词描述。此时可以先列出它做的事情，观察哪些步骤有独立的输入和输出。

拆分也有代价。不必为了让名字漂亮，把三行直观代码拆成五个函数。判断标准是读者是否更容易理解修改会影响什么。

## 给未来的阅读留一点上下文

名字表达“是什么”，注释可以解释“为什么”。特别是为了兼容外部系统而保留的限制，应写清楚约束来自哪里。否则下一位维护者可能很合理地删掉它。
